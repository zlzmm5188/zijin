# 字段级缓存架构说明

**版本：v1.0**  
**创建时间：2024-11-10**  
**架构决策：性能优化 + 跨端一致性 + 风控**

---

## 🎯 为什么需要字段级缓存？

### 问题

1. **性能问题**：300+项目时，实时计算 `total_rate`、`sold`、`remain` 太慢
2. **一致性问题**：多端（web/app/小程序）如果各自计算，容易不一致
3. **风控问题**：前端参与计算容易被篡改

### 解决方案

**字段级缓存**：将计算结果直接存储在数据库中

---

## 📦 缓存字段设计

### invest_projects 表新增字段

| 字段名 | 类型 | 说明 | 更新时机 |
|--------|------|------|----------|
| `total_rate` | DECIMAL(6,3) | 总收益率缓存（基础+临时+活动） | 项目参数修改时 |
| `sold` | DECIMAL(18,2) | 已募集金额缓存 | 每次投资成功后 |
| `remain` | DECIMAL(18,2) | 剩余额度缓存 | 每次投资成功后 |
| `cache_updated_at` | DATETIME | 缓存更新时间 | 每次更新时 |

### 计算公式

```sql
total_rate = base_rate + added_rate + gift_rate
sold = total_invested
remain = total_quota - sold
schedule = (sold / total_quota) * 100
```

**注意**：`total_rate` 不包含VIP加息（VIP是用户级别的）

## 🔄 缓存更新机制

### 自动更新时机

1. **投资成功后** → 自动调用 `ProjectCacheService::updateCache($projectId)`
2. **项目参数修改后** → 管理后台保存时调用
3. **定时刷新** → 每小时执行一次（cron/update-project-cache.php）

### 更新流程

```php
// 投资成功后
$orderId = createOrder(...);

// 更新项目统计
updateProjectStats($projectId, $amount);

// 【自动更新缓存】⭐
ProjectCacheService::updateCache($projectId);

// 其他操作...
```

## ⚡ 性能对比

### 实时计算方式（弃用）

```
每次请求：
1. 读取项目数据
2. 计算 total_rate = base + added + gift
3. 计算 sold = total * schedule / 100
4. 计算 remain = total - sold
5. 返回结果

300个项目 × 1000请求/秒 = 大量重复计算
```

### 字段级缓存方式（当前）

```
每次请求：
1. 读取项目数据（含缓存字段）
2. 加上用户VIP（唯一计算）
3. 直接返回

300个项目 × 1000请求/秒 = 只查询，无计算
性能提升：90%+
```

## 🔧 ProjectCacheService

### 核心方法

```php
/**
 * 更新单个项目缓存
 */
ProjectCacheService::updateCache($projectId);

/**
 * 批量更新所有项目缓存
 * 定时任务调用
 */
ProjectCacheService::updateAllCache();
```

### 调用时机

**立即更新：**
- 投资成功后
- 项目参数修改后
- 管理员手动刷新

**定时更新：**
- 每小时执行一次
- 宝塔面板配置：`php /www/wwwroot/providence-admin/cron/update-project-cache.php`

## 🌐 跨端一致性

### 问题场景

**如果没有缓存：**
```
Web前端：计算 sold = total * schedule / 100
App前端：计算 sold = total * schedule / 100
小程序：计算 sold = total * schedule / 100

问题：
1. 三端都要写相同逻辑
2. 浮点数精度可能不一致
3. 一处改了其他忘记改
```

### 字段级缓存方案

```
后端：维护 sold 字段
所有前端：直接读取 sold

优势：
1. 后端统一维护
2. 精度完全一致
3. 修改只改一处
4. 跨端通用
```

---

## 🛡️ 风控一致性

### SRS核心原则

**后端统一字段，前端禁止逻辑**

```
后端职责：
✓ 计算所有业务数值
✓ 维护缓存字段
✓ 保证数据一致性

前端职责：
✓ 显示后端数据
✓ 收集用户输入
✗ 不做任何计算
✗ 不推测业务逻辑
```

### 防篡改

```
前端无法篡改计算结果
前端无法伪造数据
所有数值来自后端可信源
```

## 📋 维护规范

### 缓存更新SOP

1. **投资成功**
```php
createOrder();
updateProjectStats();
ProjectCacheService::updateCache($projectId);  // 自动
```

2. **修改项目参数**
```php
updateProject($projectId, $params);
ProjectCacheService::updateCache($projectId);  // 手动调用
```

3. **定时刷新**
```bash
# 宝塔面板 → 计划任务
# 每小时执行
php /www/wwwroot/providence-admin/cron/update-project-cache.php
```

### 缓存一致性检查

**监控指标：**
- `cache_updated_at` 超过1小时 → 告警
- `sold` != `total_invested` → 数据不一致告警
