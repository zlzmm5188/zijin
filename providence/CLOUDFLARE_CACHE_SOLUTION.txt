================================================
CloudFlare 缓存问题 - 终极解决方案
================================================

🔴 问题现象
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
- 代码已修改，但网页显示旧内容
- 已开启开发模式，但仍有缓存
- 不同子域名访问，仍显示旧版本
- 强制刷新（Ctrl+Shift+R）无效

🎯 根本原因
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
CloudFlare的缓存层级：
1. 边缘服务器缓存（全球CDN节点）
2. 浏览器缓存（本地）
3. 中间代理缓存

即使开启开发模式，缓存清除也需要时间传播！

✅ 解决方案（按有效性排序）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

方案1: 使用Purge Everything（最彻底）⭐⭐⭐⭐⭐
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. 登录 CloudFlare Dashboard
2. 选择域名：agx.bi
3. 缓存 → 配置
4. 点击「清除所有内容」(Purge Everything)
5. 等待30秒-2分钟
6. 重新访问

注意：每次修改都要手动清除！

方案2: 修改缓存规则（一劳永逸）⭐⭐⭐⭐⭐
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. CloudFlare → 规则 → 页面规则
2. 创建页面规则：
   URL: *agx.bi/*.html
   设置: 缓存级别 = "绕过"
3. 保存并部署

或者：
1. 缓存 → 配置
2. 浏览器缓存TTL → 选择「尊重现有标头」
3. 缓存级别 → 选择「无查询字符串」

好处：以后修改立即生效，无需清除缓存！

方案3: 使用查询参数（临时方案）⭐⭐⭐⭐
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
访问时添加随机参数：
https://agx.bi/projects.html?nocache=$(date +%s)

或者：
https://agx.bi/projects.html?v=1762558000

缺点：每次都要手动添加参数

方案4: nginx添加Cache-Control头（推荐）⭐⭐⭐⭐⭐
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
编辑nginx配置（宝塔面板）：

location ~* \.(html)$ {
    add_header Cache-Control "no-cache, no-store, must-revalidate";
    add_header Pragma "no-cache";
    add_header Expires "0";
}

好处：从源头控制缓存，CloudFlare会尊重这些头！

方案5: 使用CloudFlare API自动清除⭐⭐⭐
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
已创建脚本（需要Zone ID）：
  ./clear-cf-cache-now.sh

获取Zone ID：
1. CloudFlare Dashboard
2. 概览 → 右侧 → API部分
3. 复制 Zone ID

================================================
推荐方案组合
================================================

最佳组合（开发期间）:
  ✓ 方案2：设置缓存规则「绕过HTML」
  ✓ 方案4：nginx添加no-cache头
  
效果：修改后立即生效，无需手动清除！

临时快速方案:
  ✓ 方案1：手动清除缓存
  ✓ 方案3：访问时添加?v=参数

================================================
验证缓存是否清除
================================================

方法1: 查看响应头
  F12 → Network → 点击文件 → Headers
  查看：
    - Cache-Control
    - CF-Cache-Status
    - Age

方法2: 访问测试页面
  https://agx.bi/test-btn-style.html
  （刚创建的，无缓存）
